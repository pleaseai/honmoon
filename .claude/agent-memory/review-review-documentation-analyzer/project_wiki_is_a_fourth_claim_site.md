`wiki/` is a hand-maintained VitePress site, not generated from `ARCHITECTURE.md`. Its pages say
their content is "grounded in" that file, which reads as derivation and is not: amending
`crates/AGENTS.md`, the root `AGENTS.md` or `ARCHITECTURE.md` reaches nothing under `wiki/`.

Measured twice. PR #206 retired the claim that `honmoon-core` does no I/O (issue #166 settled that
it opens the operator's JSONL audit sink) and amended the three normative documents; the wiki kept
asserting the opposite in **five** pages and in the generated `llms-full.txt`, which is issue #207.
Two of those five were not in #207's own list — the issue named `deep-dive/architecture.md`,
`getting-started/overview.md` and `onboarding/staff-engineer-guide.md`, and a sweep found
`deep-dive/policy-engine.md` and `onboarding/contributor-guide.md` carrying it too. So on a rule change, **search `wiki/` rather
than trusting an enumeration of pages**, including one written by the issue.

**The wiki's fix is a rewrite, not a phrase swap.** The normative documents carry a rule in one
table cell or bullet, so amending them is a one-paragraph change. The wiki builds the rule into an
argument over several paragraphs — "with every byte of I/O pushed to the edges around it" was a
load-bearing step in the staff guide's opening, not a phrase. A sentence patched in place inside
an argument that still assumes the old premise reads worse than the error it replaced. Flag a
wiki fix that changed only the sentence containing the retired words.

**Mechanical facts worth having before reviewing a `wiki/` diff:**

- `wiki/llms-full.txt` is generated by `wiki/.vitepress/gen-llms-full.mjs` and inlines verbatim
  the pages the generator lists — every page but `index.md`. Any page edit must be followed by
  `cd wiki && bun .vitepress/gen-llms-full.mjs`.
  A hand-patched `llms-full.txt`, or a page edit with no corresponding change to it, is a defect
  — the generator's output is byte-comparable, so this is checkable rather than a judgement call.
  `wiki/llms.txt` is *not* generated; it is a hand-maintained link index of one-line summaries.
- `wiki/**` is in the root `eslint.config.mjs` ignore list, confirmed with
  `eslint --print-config`. The `markdown/no-missing-atx-heading-space` trap that a `#123`
  reference wrapping to column 1 triggers elsewhere in this repo does **not** fire on wiki pages.
  The wiki's own gate is `cd wiki && bun run build`; `bun run lint` says nothing about it.
- Citations into other files go stale when those files are edited, and the link still resolves,
  so nothing surfaces it. #206's insert into `ARCHITECTURE.md` moved its Architecture Invariants
  section and left five wiki anchors naming the wrong lines. Tracked as issue #244, which also
  records two anchors (`ARCHITECTURE.md:117-129`, `:139`) still stale at the time of writing.

**What `scripts/check-wiki-io-claim.ts` does and does not cover.** Added in the #207 PR. It fails
`bun test` if a published wiki document uses one of the retired phrasings, or if a page states
what `honmoon-core` lacks without naming the audit sink. Do **not** cite it as enforcement of wiki
accuracy generally: rule 1 is a list of known strings, so a fresh paraphrase ("the core never
touches the disk") passes, and rule 2 fires only on a page pairing "transport-agnostic" with an
explicit capability-absence phrase. The module doc states the split. An overstated guard is what
stops a reviewer from looking, which is the failure #206 hit twice.

**Why:** the wiki is the only one of the four claim sites that users read, and it is the one the
repository's own tooling and review habits reach last — it has a separate deploy workflow, a
separate `package.json`, a separate `AGENTS.md`, and it is excluded from the root linter.

**How to apply:** when a diff amends a rule in `crates/AGENTS.md`, the root `AGENTS.md` or
`ARCHITECTURE.md`, grep `wiki/` for the retired claim and flag any page still carrying it, at high
confidence — the precedent is that this is missed by default rather than occasionally. When a diff
edits a `wiki/` page, check that `wiki/llms-full.txt` moved with it. See
[[honmoon-crate-table-convention]] for the same propagation problem inside the normative documents
themselves.
